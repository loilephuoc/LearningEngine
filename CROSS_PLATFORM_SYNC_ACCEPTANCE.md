# Cross-Platform Sync & Portable Backup — Acceptance Checklist

## Checklist

### 1. Portable Backup (.lebak v2)
- [x] Portable backup archive is versioned (`backupSchemaVersion = 2`) and self-describing (`manifest.json`).
- [x] Desktop can create full portable backup with all packages, JSON data, and media files.
- [x] Desktop can inspect and preview portable backup before restore.
- [x] Desktop can safely restore portable backup with automatic safety backup and atomic rollback on failure.
- [x] Android can create portable backup with Android supplements (preferences, recordings, lockscreen background).
- [x] Android can preview and restore portable backup produced by Desktop.
- [x] Desktop can preview and restore portable backup produced by Android.
- [x] Corrupt, truncated, or tampered backup files are rejected during preflight without mutating live data.

### 2. Differential Sync Changeset (.lesync v1)
- [x] Desktop can export a differential sync package containing only modified content items and newly added/modified media assets.
- [x] Package scoping supported: exporting Package A never touches Package B.
- [x] First-baseline requirement: Attempting to sync unknown packages recommends Full Backup/Restore.
- [x] Unchanged large media assets are NOT included in differential sync packages (deduplicated by SHA-256).
- [x] Android can import Desktop sync package and apply field updates and new media cleanly.
- [x] Audio generated by Desktop EdgeTTS is properly packaged and transferred to Android.
- [x] Android can export review events created during mobile study.
- [x] Desktop can import Android review events; duplicate reviews are deduplicated with zero data corruption.
- [x] FSRS memory states on Desktop converge to reflect reviews done on Android.

### 3. Conflict Detection & Data Safety
- [x] Same content changed on only one device: automatically merged.
- [x] Same content changed concurrently on both devices: conflict detected and presented in conflict report UI.
- [x] Conflict resolution strategies available: Merge field level, Keep local, Apply incoming.
- [x] User changes are never silently discarded or overwritten.
- [x] Restore operations are strictly transactional (validate -> stage -> safety backup -> apply -> verify -> commit/rollback).
- [x] Existing user data, package data, review history, and settings are preserved.

### 4. UI & Workflow
- [x] Desktop Settings provides clear actions: Sao lưu (.lebak), Khôi phục (.lebak), Xuất đồng bộ (.lesync), Nạp đồng bộ (.lesync).
- [x] Desktop displays informative preview on sync import (content items updated, media reused, review events merged, conflicts).
- [x] Android UI displays Differential Sync card alongside Full Backup card with conflict strategy selector.
