# Cross-Platform Sync & Portable Backup — Acceptance Checklist

## Checklist

### 1. Portable Backup (.lebak v2)
- [ ] Portable backup archive is versioned (`backupSchemaVersion = 2`) and self-describing (`manifest.json`).
- [ ] Desktop can create full portable backup with all packages, JSON data, and media files.
- [ ] Desktop can inspect and preview portable backup before restore.
- [ ] Desktop can safely restore portable backup with automatic safety backup and atomic rollback on failure.
- [ ] Android can create portable backup with Android supplements (preferences, recordings, lockscreen background).
- [ ] Android can preview and restore portable backup produced by Desktop.
- [ ] Desktop can preview and restore portable backup produced by Android.
- [ ] Corrupt, truncated, or tampered backup files are rejected during preflight without mutating live data.

### 2. Differential Sync Changeset (.lesync v1)
- [ ] Desktop can export a differential sync package containing only modified content items and newly added/modified media assets.
- [ ] Unchanged large media assets are NOT included in differential sync packages.
- [ ] Android can import Desktop sync package and apply field updates and new media cleanly.
- [ ] Audio generated by Desktop EdgeTTS is properly packaged and transferred to Android.
- [ ] Android can export review events created during mobile study.
- [ ] Desktop can import Android review events; duplicate reviews are deduplicated with zero data corruption.
- [ ] FSRS memory states on Desktop converge to reflect reviews done on Android.

### 3. Conflict Detection & Data Safety
- [ ] Same content changed on only one device: automatically merged.
- [ ] Same content changed concurrently on both devices: conflict detected and recorded in conflict report.
- [ ] User changes are never silently discarded or overwritten.
- [ ] Restore operations are strictly transactional (validate -> stage -> safety backup -> apply -> verify -> commit/rollback).
- [ ] Existing user data, package data, review history, and settings are preserved.

### 4. UI & Workflow
- [ ] Desktop Settings / Library provides clear actions: Backup, Restore, Export Sync, Import Sync.
- [ ] Desktop displays informative summary on sync import (content items updated, media added, review events merged, conflicts).
- [ ] Android UI displays clear feedback during backup/restore and sync operations.

### 5. Quality & Engineering
- [ ] Minimum test matrix passes:
  - `PortableManifestTest`
  - `PortableBackupWriterTest`
  - `PortableBackupReaderTest`
  - `BackupValidationTest`
  - `IdentityMappingTest`
  - `MediaHashTest`
  - `MediaDeduplicationTest`
  - `ContentChangeMergeTest`
  - `ReviewEventMergeTest`
  - `ReviewEventDeduplicationTest`
  - `ConflictDetectionTest`
  - `ConflictResolutionTest`
  - `MigrationTest`
  - `RestoreRollbackTest`
- [ ] `./gradlew.bat clean test` exits with `BUILD SUCCESSFUL`.
- [ ] Git worktree is clean and all documentation is synchronized.
