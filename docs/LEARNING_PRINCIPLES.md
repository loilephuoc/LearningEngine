# Learning Principles — Learning Engine 2.0

## 1. Overview

These learning principles represent immutable pedagogical invariants for Learning Engine 2.0. They govern product behavior, algorithm design, and UI presentation across all target platforms.

---

## 2. Core Principles

### Principle 1: Learning Should Adapt to the Learner
The engine must adapt to the learner's current knowledge state, retention history, and cognitive pace. Static, rigid review schedules or uniform card presentation formats fail to accommodate individual learning curves.

### Principle 2: Minimize Cognitive Overload
Learners must focus their mental energy on processing knowledge, not navigating complex software options or configuring algorithm parameters. The user interface must present clean, distraction-free Learning Scenes with clear next steps.

### Principle 3: Maximize Long-Term Retention
Spaced retrieval practice, active recall, and multi-modal scene rotation must be leveraged to transfer knowledge from working memory into durable long-term storage. Short-term cramming modes are explicitly subordinate to long-term memory formation.

### Principle 4: Learning Should Remain Enjoyable and Engaging
Motivation is a prerequisite for sustained learning. The system must design learning flows that foster a sense of momentum, progress, and mastery, avoiding punitive mechanics or monotonous repetition.

### Principle 5: Guided Teaching over Manual Configuration
The learner should press **Start Learning** and be guided by the engine. Manual selection of learning modes, deck filters, or scheduling steps should be unnecessary for effective study.

### Principle 6: Learning Should Never Become Repetitive
Presentation scenes must rotate deterministically (e.g., Image Prompt, Listening Prompt, Text Prompt, Typing Challenge) to prevent rote pattern matching and foster flexible, deep memory retrieval.

### Principle 7: Every Scene Must Have a Teaching Purpose
Every stage in a Learning Flow—from initial prompt to answer reveal and rating feedback—must serve a specific pedagogical objective. No UI element or interaction should exist merely for cosmetic variation.

---

## 3. Governance

Any proposal to introduce user-facing configuration that shifts pedagogical decisions onto the learner, or any UI design that increases cognitive distraction, violates these principles and must be rejected.
